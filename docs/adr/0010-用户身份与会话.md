# 0010 用户身份与会话

- 状态：提议中
- 日期：2026-10-23
- 涉及模块：`auth` `db` `api-public` `api-admin` `web-shared` `web-chat` `web-admin` `build`
- 方案文档：[身份与权限](../方案/身份与权限.md)

## 背景

问答端没有鉴权，管理端只有一个共享的管理员密码，token 存在内存里（ADR 0004）。服务端部署后，“只监听本机”这道防线不再存在。同时，按人过滤文档的前提是先知道提问的人是谁。现有的 import-linter 契约禁止问答端依赖 `auth`，问答端没法接入登录。

## 决策

**两种运行模式**

- `KB_AUTH_MODE=local`（默认）：行为与现在一致，问答免登录，管理端用密码。
- `KB_AUTH_MODE=sso`：两个应用都必须使用企业身份登录。

**身份源**

- 身份源抽象为 `IdentityProvider`，首期只实现飞书网页应用 OAuth（授权码 + PKCE + state）。
- 后端完成全部 OAuth 交互，`user_access_token` 用完即丢，不落库，也不下发前端。
- 登录与阶段 1 的同步使用同一个飞书自建应用，用户标识统一为 `open_id`。

**会话**

- 使用服务端会话，存在 `sessions` 表中，只保存 token 的 SHA-256；通过 HttpOnly Cookie 下发。
- 问答与管理使用不同的 Cookie 名称，会话绑定所属应用。原因是浏览器的 Cookie 不按端口隔离。
- 两个应用分别设置空闲过期和绝对过期，登录时轮换会话，用户停用时吊销其全部会话。
- 防 CSRF：`SameSite=Lax` + 自定义请求头 + Origin 白名单。
- 管理端的 Bearer token 方案在两种模式下都改为 Cookie 会话。

**授权**

- 管理端改为 RBAC：
  - 角色固定为 `admin`、`knowledge_manager`、`member`。
  - 权限点在代码中定义，每个管理接口必须声明所需的权限点。
- 初始管理员通过 `KB_BOOTSTRAP_ADMINS` 指定，只在系统中还没有任何 admin 时生效；另提供运维命令 `kb-studio grant-role`。
- 现有管理员密码降级为应急口令。`sso` 模式下默认关闭，开启后只允许本机访问；应急登录在问答端的访问范围为空。
- 管理端写操作和登录事件写入只能追加的审计日志。

**模块边界**

- 新增 `identity` 层，负责身份源、会话、主体解析和访问范围，问答端和管理端都可以依赖。
- `auth` 改为只有管理应用可以依赖的包，负责 RBAC、应急口令和审计。
- 分层调整为 `cli → apps → api → ingest | auth → evaluation → query → identity → rag | db | storage → settings`。
- “问答端只读”明确为“问答端对知识库只读”：可以写入用户自己的数据（会话；阶段 4 的对话记录与反馈），不能改变文档、索引、权限和设置。禁止依赖的模块列表不变。

## 备选方案

- **JWT 无状态会话**：无法立即吊销，离职、停用、角色变更后旧 token 在过期前都有效，排除。
- **前端持有 token（sessionStorage + Bearer）**：XSS 可以直接读取 token；服务端部署后风险明显高于 HttpOnly Cookie，排除。
- **通用 OIDC 库对接**：飞书不是标准 OIDC 提供方，套用通用库反而要处理大量差异。先实现飞书，接口按身份源抽象，以后接入标准 OIDC 时再加实现。
- **问答端直接依赖 `auth`**：会把应急口令、角色管理等管理能力带进问答端的依赖图，违背 ADR 0007 的隔离目标，排除。

## 影响

- 采纳后，ADR 0004 的状态改为“已被 0010 取代”。
- ADR 0007 中“问答端只读”契约的含义按本 ADR 调整，契约内容由 [ADR 0011](./0011-文档权限模型与检索过滤.md) 和本 ADR 共同修改 `backend/pyproject.toml`。
- 数据库迁移 2：新增 `users`、`user_groups`、`user_roles`、`sessions`、`oauth_states`、`audit_logs` 表，已有的管理员密码保留为应急口令。
- **破坏性** 管理端登录接口从 `POST /api/admin/auth/login`（返回 token）改为 Cookie 会话；前端同步修改。
- 后端重启不再需要重新登录。
- 服务端部署建议问答和管理使用不同的主机名，写入部署说明。
