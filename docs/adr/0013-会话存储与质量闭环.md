# 0013 会话存储与质量闭环

- 状态：提议中
- 日期：2026-10-23
- 涉及模块：`query` `eval` `db` `api-public` `api-admin` `web-chat` `web-admin`
- 方案文档：[对话与质量闭环](../方案/对话与质量闭环.md)
- 相关决策：[ADR 0015 会话服务与独立数据库](./0015-会话服务与独立数据库.md)

## 背景

问答目前没有上下文，刷新即丢失；线上回答的好坏无从得知；回归测试只保留一个通过率，判断不了语义，也无法比较两次运行。规划建议用 LangGraph Checkpointer 保存会话。但会话记录需要按用户查询、按权限校验、按期限清理，还要关联反馈和检索追踪，这些都是业务数据的需求。

## 决策

**会话存储**

- 会话、消息、反馈存放在独立的会话数据库中，由独立的会话服务读写（ADR 0015），不使用 LangGraph Checkpointer。
- 消息保存模型原文、来源快照（`doc_id`、版本、章节、分数，不含片段正文）、检索追踪、索引版本、模型和耗时。

**上下文**

- 最近 3 轮对话用于问题改写和理解指代。
- 生成时不带历史检索片段，每轮重新检索。
- 事实只能来自本轮资料。

**权限与隐私**

- 查看历史时，来源按当前访问范围重新校验。
- 对话只属于用户本人，管理员没有浏览入口。
- 默认保留 180 天，用户可以随时物理删除。

**用户反馈**

- 支持点赞、点踩和原因分类，提交时生成该轮问答的快照，表示用户同意提供给知识管理员。
- 后台处理反馈，可以转为回归用例；期望结果必须由知识管理员确认。

**评测**

- 每次运行的完整结果保存在 `eval_runs`、`eval_results` 中，可以对比任意两次运行。
- 用例增加分类、多轮历史、参考答案和启用状态。

**LLM 评分**

- 从正确性、忠实度、切题度三个维度打分，评分模型单独配置，结果按回答哈希缓存。
- 与人工打分的一致率达到 80% 以上之后才参与把关。
- 关键词判定（ADR 0006）仍然是“通过 / 不通过”的依据。

**切换把关**

- 默认 `warn`：通过率低于当前索引时，切换前提示。
- `block` 模式下可以填写原因后强制切换，写入审计日志。
- 权限用例失败时，任何模式下都不能切换。
- 回退不受把关限制。

**模块边界**

- 会话数据只经由 `conversation_client` 访问，边界契约见 ADR 0015。
- 评测相关的表（`eval_runs`、`eval_results`、`eval_cases`）留在知识库数据库中。

## 备选方案

- **LangGraph Checkpointer**：存的是图状态的序列化快照。列出会话、关联反馈、按权限校验、按期限清理都要另建索引或解析快照，而当前链路没有需要中断恢复的图，排除。阶段 5 需要可恢复的 Agent 执行状态时，再单独引入。
- **会话只存在前端（localStorage）**：无法跨设备、无法关联反馈和追踪信息、无法统一执行保留期限，排除。
- **用 LLM 评分替代关键词判定**：结果有波动、成本高、需要校准，只作为附加指标。
- **反馈自动生成用例**：期望结果需要人判断，自动生成会把错误的答案固化进回归集，排除。

## 影响

- 知识库数据库迁移 3：新增 `eval_runs`、`eval_results`；`eval_cases` 增加字段，带默认值。会话相关的表在独立的会话数据库中（ADR 0015）。
- **破坏性** SSE `error` 事件的数据由字符串改为 `{code, message}`；新增 `meta` 事件，`done` 增加字段，前端同步修改。
- `index_versions.eval_pass_rate` 保留，取最近一次正式运行的结果。
- 新增的 import-linter 契约见 ADR 0015。
- 规划中阶段 4 的 Recall@K 已经由 [ADR 0012](./0012-混合检索与重排序.md) 提前到阶段 3。
