# 0002 索引版本与蓝绿切换

- 状态：已采纳
- 日期：2026-10-20
- 涉及模块：`ingest` `rag`

## 背景

更换 Embedding 模型或分块参数后，向量空间和切块结果都会变，不能在原 collection 上增量叠加。直接覆盖原索引，出问题时又没法回退。

## 决策

- 每个索引版本对应一个独立的 collection（`kb_v{id}`），版本记录中固化 `embedding_model`、`chunk_size`、`chunk_overlap`。
- 重建在后台任务中执行，完成后自动跑回归测试并记录通过率，**不自动切换**。
- 当前版本由 `kv.current_index_id` 指定，相当于生产环境中的 collection alias；切换和回退都只改这个指针。
- 日常的增量入库只写当前版本，沿用该版本固化的参数；其他版本是快照，不受影响。

## 备选方案

- 原地重建：构建期间问答不可用，并且无法回退。
- 增量入库同时写入所有版本：成本随版本数线性增长，而且旧版本的参数可能已经不适用。

## 影响

- 回退是秒级的，不需要重新向量化。
- 切回旧快照后，之后新增或修改过的文档在该快照里缺失或版本落后，切换时会同步把这些文档标记为“待同步”。
- 磁盘占用随版本数增长，需要手动删除不再使用的版本。
