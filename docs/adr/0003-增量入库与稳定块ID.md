# 0003 增量入库与稳定块 ID

- 状态：已采纳
- 日期：2026-10-20
- 涉及模块：`ingest` `rag`

## 背景

每次全量重建的成本随知识库规模线性增长，而日常变更通常只涉及少数文档。

## 决策

- 用文件名识别同一文档，用 SHA-256 判断内容是否变化：内容没变直接跳过，不调用 Embedding。
- 块 ID 固定为 `{doc_id}:{序号}`，块元数据携带 `doc_id` 和 `version`。
- 更新文档时，先按 `where={"doc_id": id}` 删除旧块，再写入新块；删除文档同理。

## 备选方案

- 用内容哈希作为块 ID，只更新变化的块：节省更多，但切块边界移动会让大部分块的哈希都变化，收益有限，而且实现更复杂。
- 依赖 upsert 覆盖：新版本块数变少时，多出来的旧块会残留，排除。

## 影响

- 文档重命名会被当作新文档，旧文档需要手动删除。
- 粒度是文档级：一个文档有任何改动，它的所有块都会重新向量化。
