# 0001 本地三层数据架构

- 状态：已采纳
- 日期：2026-10-20
- 涉及模块：`db` `storage` `rag`

## 背景

项目用来学习工程化 RAG，需要体现“原始数据 / 元数据 / 向量索引”的分层，但不希望引入服务器部署和运维成本。

## 决策

三层全部落在本地 `data/` 目录下：

- 原始数据：`data/raw/<doc_id>/v<n>/<文件名>`，每个版本一个目录，作为真相源
- 元数据：SQLite（`data/app.db`），用标准库 `sqlite3`，每次调用新建连接，规避跨线程共享连接
- 向量索引：Chroma 本地持久化（`data/chroma/`），视为可重建的派生数据

## 备选方案

- 只用 Chroma，元数据也存进块里：做不了版本历史和文档级状态管理，排除。
- PostgreSQL + pgvector：更接近生产环境，但需要单独部署数据库，超出“零运维”的目标。

## 影响

- 删除 `data/` 即恢复初始状态；向量库损坏时可以从原始数据重建。
- 迁移到生产时，三层可以分别替换成 OSS、PostgreSQL、Milvus 或 Qdrant，业务层不受影响。
- 不支持多实例共享数据。
