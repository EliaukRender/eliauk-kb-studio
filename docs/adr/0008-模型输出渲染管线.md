# 0008 模型输出渲染管线

- 状态：已采纳
- 日期：2026-10-23
- 涉及模块：`web-shared` `web-chat` `web-admin` `eval`

## 背景

模型的回答是 Markdown，前端原先按纯文本显示，`**`、`#` 等符号会原样出现。只接入 Markdown 解析器还有三个问题：

- CommonMark 的强调规则对中文不友好，紧贴中文标点的 `**“年假”**为` 无法识别。
- 流式输出过程中语法经常处于未闭合状态，界面会闪烁。
- 回答的内容来自知识库原文和模型生成，可能夹带 HTML 或 prompt 注入内容，必须作为不可信内容处理。

## 决策

**原文不修改**

- 消息里只保存模型的原始输出，HTML 只在渲染时派生；复制、评估、排查问题都基于原文。

**分层管线**

- 规范化 → 流式补全 → 解析 → 消毒 → 渲染，每一步都是纯函数。
- 管线放在 `shared`，问答和管理两个应用共用。

**选型**

| 环节 | 选用 |
| --- | --- |
| 解析 | markdown-it + markdown-it-cjk-friendly |
| 流式补全 | remend（Vercel streamdown 的补全逻辑，零依赖） |
| 消毒 | DOMPurify |

**两层防护**

- markdown-it 关闭 HTML，DOMPurify 再做标签白名单过滤。
- 禁用图片，防止注入内容通过图片 URL 把检索内容外带出去。
- 任何一步出错都降级为转义后的纯文本。

**后端同步调整**

- 回归判定比较前去掉 Markdown 标记。
- Prompt 约定使用 Markdown，不输出 HTML 和图片。

## 备选方案

- **Prompt 要求输出纯文本**：模型不能稳定遵守，而且会失去分点、强调带来的可读性。
- **用正则清洗符号**：会误伤正文中正常出现的 `*`、`#`，也无法表达结构。
- **marked**：可以使用，但中文强调问题没有成熟的插件，安全选项也需要自己组合。
- **直接使用 streamdown 组件**：依赖 React，与 Vue 技术栈不符，所以只采用它的补全库 remend。

## 影响

- 回答中不显示图片。以后如果需要显示，必须经过图片代理和域名白名单。
- 消毒相关的单元测试必须在 jsdom 环境运行：happy-dom 下 DOMPurify 会丢失元素和属性。
- 前端新增依赖：`markdown-it`、`markdown-it-cjk-friendly`、`remend`、`dompurify`；开发依赖 `jsdom`。
