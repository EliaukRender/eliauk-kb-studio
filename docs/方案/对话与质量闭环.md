# 对话与质量闭环

- 状态：设计中（未实施）
- 对应规划：[企业知识助手演进路线 · 阶段 4](../规划/企业知识助手演进路线.md)
- 决策记录：[ADR 0013](../adr/0013-会话存储与质量闭环.md)、[ADR 0015](../adr/0015-会话服务与独立数据库.md)（提议中）
- 下游方案：[会话服务](./会话服务.md)（会话数据的存储、服务边界、内部接口与部署）
- 前置依赖：[身份与权限](./身份与权限.md)（会话归属于用户）；[检索质量](./检索质量.md)（问题改写、检索追踪、检索指标）
- 涉及模块：`conversation` `query` `eval` `db` `api-public` `api-admin` `web-chat` `web-admin` `build`

## 1. 背景

| 能力 | 现状 | 差距 |
| --- | --- | --- |
| 对话 | 每次提问相互独立；刷新页面后记录消失 | 无法追问；无法回看 |
| 线上质量 | 只能靠人工反馈 | 不知道哪些回答不好、为什么不好 |
| 回归测试 | 6 条关键词用例；结果只保留一个通过率（`index_versions.eval_pass_rate`） | 判断不了语义；没有历史记录，无法比较两次运行 |
| 改进闭环 | 发现问题 → 人工记下来 → 手动加用例 | 线上问题沉淀不进回归集 |

阶段 4 要形成闭环：**线上问答 → 用户反馈 → 定位原因 → 转为回归用例 → 修复后评测不退步 → 发布**。

## 2. 目标与非目标

**目标**

- 多轮对话：会话持久化、可以回看和删除；追问时自动补全上下文。
- 用户反馈：点赞 / 点踩，点踩时选择原因；知识管理员在后台处理反馈，一键转为回归用例。
- 每条回答可以追溯：使用的索引版本、检索追踪信息、模型、耗时。
- 评测升级：用例分类、多轮用例、参考答案、LLM 评分；运行记录持久化、可以对比；切换索引前按规则做质量把关。
- 隐私：对话记录属于用户本人，管理员默认看不到；设置保留期限。

**非目标**

- 会话共享、协作对话、导出对话。
- 在线 A/B 实验（按流量分配不同参数）：用离线评测和试运行代替。
- 自动从反馈生成用例而无人审核：转为用例必须由知识管理员确认期望结果。
- 用 LLM 评分完全替代关键词判定。

## 3. 多轮对话

### 3.1 存储方案

会话数据（对话、消息、反馈）存放在**独立的会话数据库**中，由**独立的会话服务**读写，问答应用和管理应用只能通过服务接口访问。存储结构、服务边界、内部接口、降级策略和部署方式见[会话服务](./会话服务.md)，本文只描述业务规则。

规划中写的是“结合 LangGraph Checkpointer 保存会话上下文”，这里不采用，理由如下：

| 需求 | Checkpointer | 会话服务 |
| --- | --- | --- |
| 按用户列出会话、分页、改标题 | 存的是图状态的序列化快照，需要另外建索引表 | 直接查询 |
| 每条回答关联索引版本、来源、追踪信息、反馈 | 需要塞进状态，再从快照中解析 | 普通字段 |
| 删除单个会话、按保留期限清理 | 依赖其内部表结构 | 服务内置 |
| 管理侧只能读反馈，不能读对话 | 无法表达 | 由服务接口保证 |
| 独立数据库、独立备份 | 跟随所在数据库 | 天然独立 |
| 当前链路是否需要 | 当前是单次检索加生成，没有需要中断和恢复的图 | — |

阶段 5 引入 Agent 时，如果需要可中断、可恢复的执行状态，再单独使用 Checkpointer 保存“执行状态”，它与“对话记录”是两回事。

### 3.2 上下文策略

| 用途 | 使用的历史 | 说明 |
| --- | --- | --- |
| 问题改写 | 最近 3 轮的问题和回答摘要（回答截断到 200 字） | 见[检索质量](./检索质量.md)第 9 节 |
| 生成回答 | 最近 3 轮的问题和回答（总长度不超过 `history_max_chars`，默认 3000 字），**不带历史检索片段** | 历史片段可能已经无权查看或已经过时；每轮重新检索 |
| 展示 | 全部 | 分页加载 |

Prompt 新增一个历史消息区，放在系统提示和本轮资料之间，并约束：事实只能来自本轮的 `<context>`，历史只用来理解指代。

### 3.3 并发与中断

- 同一会话同时只能有一个回答在生成：会话服务发现该会话已有 `streaming` 状态的消息时返回 409。两个标签页同时发送时，后发的一方会看到提示。
- 用户中途停止或断开连接时，已经生成的部分保存下来，状态记为 `interrupted`，界面上显示“已停止”。
- 问答应用崩溃时，消息的租约到期，会话服务自动将其改为 `interrupted`，保留最后一次保存的进度。
- 生成出错时状态记为 `failed`，保存错误类别（不保存堆栈）；用户可以“重新生成”，重新生成会作为同一个问题的新回答，旧回答保留。
- 会话服务不可用时，问答照常进行，只是不带上下文、不保存，并提示用户（见[会话服务](./会话服务.md)第 9 节）。

### 3.4 历史中的权限

- 查看历史时，问答应用从会话服务读出消息后，按当前访问范围重新校验每条回答的来源（会话服务不理解来源的含义，也不做权限校验）。已经无权查看的来源只显示“该来源已无权查看”，不显示标题和片段。
- 回答正文本身保持不变：它在生成时已经展示给了这个用户，事后隐藏没有意义，反而会让历史无法理解。
- 来源快照只保存 `doc_id`、版本、章节和分数，不保存片段正文；展示时从当前数据读取，读不到时显示“该版本已不存在”。这样历史记录里不会长期留存受限内容的副本。

### 3.5 保留与删除

- 用户可以删除单个会话或清空全部会话。删除后立即不可见，24 小时内物理删除（消息、追踪信息一起删除）；已经提交的反馈会保留，但与会话断开关联，只保留反馈本身附带的快照（见 4.2）。
- 保留期限 `KB_CONVERSATION_RETENTION_DAYS`，默认 180 天，由会话服务每日清理。
- 用户离职或停用 30 天后，删除其全部会话。
- 管理员没有浏览用户会话的入口，会话服务也不提供这类接口。运营统计只用聚合数据（问答量、点踩率、拒答率），不展示具体问题。
- 隐私说明：问答页首次使用时提示“对话会保存 180 天，可以随时删除；提交反馈时，该轮问答会提供给知识管理员用于改进”。
- 是否向用户展示历史由部署级策略 `KB_CONVERSATION_HISTORY` 决定（`enabled` / `session_only` / `disabled`），见[会话服务](./会话服务.md) 10.1。

## 4. 用户反馈

### 4.1 交互

- 每条回答下方有点赞和点踩。点踩时弹出原因（可多选）和可选的补充说明（500 字以内）：

| 原因 | 代码 | 通常对应的问题 |
| --- | --- | --- |
| 答案不对 | `incorrect` | 生成错误，或资料本身有误 |
| 没回答我的问题 | `irrelevant` | 改写或检索偏了 |
| 引用的资料不对 | `bad_source` | 检索或排序问题 |
| 资料已经过时 | `outdated` | 文档需要更新 |
| 应该能回答，却说没有找到 | `false_refusal` | 召回不足，或门槛太高 |
| 其他 | `other` | — |

- 每个用户对每条回答只有一条反馈，可以修改，也可以撤回。

### 4.2 反馈快照

提交反馈即视为用户同意把这一轮问答提供给知识管理员，所以反馈记录自带快照，不依赖会话是否还在。反馈和快照存放在会话数据库中：

- 原问题、改写后的检索问题、回答原文、来源（`doc_id`、版本、章节、分数）、检索追踪信息、索引版本、模型、运行参数快照。
- 不保存片段正文，理由同 3.4。
- 不保存更早的对话轮次，只保存该轮问答；多轮场景下，改写后的问题已经包含必要的上下文。

### 4.3 后台处理

后台新增“反馈”页面，数据由管理应用通过会话服务的反馈接口读取（管理应用的服务令牌只有反馈权限）：

- 列表：按状态（`open` 待处理 / `triaged` 已定位 / `converted` 已转用例 / `dismissed` 已忽略）、原因、时间、索引版本、文档筛选；按文档统计点踩次数，用来发现“问题文档”。
- 详情：问题、改写结果、回答、来源列表，以及检索追踪（向量和关键词各自的排名、被门槛挡掉的候选、重排序分数）。知识管理员通常可以从这里直接判断问题出在改写、召回、排序、门槛还是生成。
- 片段正文按查看者自己的访问范围展示，看不到的显示标题和“无权查看正文”。
- 处理操作：标记原因、指派处理人、填写处理说明、忽略、**转为回归用例**。

### 4.4 转为回归用例

| 用例字段 | 预填内容 |
| --- | --- |
| 问题 | 改写后的检索问题（多轮场景）或原问题，可以修改 |
| 期望文档 | 回答引用的文档，由知识管理员修正 |
| 期望关键词 | 空，必须填写；`false_refusal` 以外的拒答类反馈可以改为拒答用例 |
| 参考答案 | 空，可选 |
| 分类标签 | 按反馈原因预填 |
| 来源 | `source_feedback_id` 关联原反馈，用例详情可以跳回反馈 |

回归用例存放在知识库数据库中；转换后，管理应用调用会话服务把反馈状态改为 `converted`，并写入 `linked_ref`。两边各自保存对方的引用，不建跨库外键。之后修复问题（更新文档、调整参数、重建索引）时，这条用例会在回归测试中验证修复效果，并防止以后退步。

## 5. 评测升级

### 5.1 用例结构

`eval_cases` 扩展：

| 字段 | 说明 |
| --- | --- |
| `tags` | 分类标签，如 `数字`、`标识`、`口语`、`多文档`、`拒答`、`权限`、`多轮` |
| `history` | 多轮用例的前序对话 `[{question, answer}]`，用来评测改写；为空表示单轮 |
| `expected_doc_ids` | 期望文档（阶段 3 已加入） |
| `reference_answer` | 参考答案，LLM 评分时使用；可以为空 |
| `principals` | 以哪些主体运行（阶段 2 已加入） |
| `enabled` | 停用的用例不参与运行，保留历史 |
| `source_feedback_id` | 来自哪条反馈 |
| `updated_at` | 用例修改后，历史结果中会标出“用例已变化”，避免拿不同版本的用例做比较 |

### 5.2 运行记录

当前只把通过率写在 `index_versions` 上。改为每次运行保存完整结果：

- `eval_runs`：运行对象（索引版本）、触发方式（重建后自动 / 手动 / 试运行）、运行参数快照、模型名称、汇总指标、开始和结束时间、状态。
- `eval_results`：每条用例的回答、关键词判定结果、LLM 评分、检索指标、追踪信息、耗时。
- 后台可以选两次运行做对比：汇总指标的差值，以及“由通过变为失败”“由失败变为通过”的用例列表。
- `index_versions.eval_pass_rate` 保留，取该版本最近一次正式运行（非试运行）的结果，兼容现有页面。
- 运行记录保留最近 200 次，试运行保留 7 天。

### 5.3 LLM 评分

| 维度 | 问题 | 依据 |
| --- | --- | --- |
| 正确性 `correctness` | 回答与参考答案的事实是否一致 | 参考答案；没有参考答案时跳过 |
| 忠实度 `faithfulness` | 回答中的事实是否都能在检索片段中找到 | 本次检索片段 |
| 切题度 `relevance` | 是否回答了问题本身 | 问题 |

- 每个维度 1–5 分，要求输出 JSON（分数加一句理由），`temperature=0`。
- 评分模型单独配置（`judge_model`），建议与生成模型不同，减少“自己给自己打高分”的偏差。评分模型的数据外发要求与生成模型相同。
- 评分结果按 `(用例 ID, 回答哈希, 评分模型, 评分规则版本)` 缓存，同样的回答不重复评分。
- 评分 Prompt 与规则版本一起固化，修改规则时版本号加一，历史结果仍可以解释。
- 拒答用例不做 LLM 评分，仍用规则判定。

**校准**：LLM 评分在正式用于把关之前，先用不少于 30 条人工打分的样本校准，与人工结论一致率达到 80% 以上才能启用把关。校准之前只作为参考指标展示。

### 5.4 判定与把关

- 关键词判定（ADR 0006）保持不变，仍是每条用例“通过 / 不通过”的依据。
- LLM 评分和检索指标作为附加指标出现在报告中。
- 切换索引时的把关规则（`KB_EVAL_GATE`，默认 `warn`）：

| 规则 | 不满足时 |
| --- | --- |
| 关键词通过率不低于当前索引最近一次运行的结果 | `warn`：切换前弹窗提示差异；`block`：拒绝切换 |
| `权限` 标签的用例全部通过 | 任何模式下都拒绝切换：权限用例失败意味着可能泄露 |
| 校准后的 LLM 平均分不低于当前索引减 0.2 | 同第一条 |

- `block` 模式下可以强制切换，但必须填写原因，写入审计日志。
- 回退（切回旧索引）不受把关限制，保证出问题时可以立即恢复。

### 5.5 成本控制

- 重建后的自动评测默认只跑关键词判定和检索指标；LLM 评分需要手动触发，或者设置 `eval_auto_judge=true`。
- 单次运行显示预计的模型调用次数；超过 `eval_max_cases`（默认 300）条时分批执行。

## 6. 模块边界

```text
backend/src/kb_studio/
  conversation/              会话服务：独立数据库，结构见会话服务方案第 5 节
  conversation_client/       问答和管理应用访问会话服务的唯一入口
  evaluation/
    runner.py                单轮与多轮用例、检索指标、运行记录
    judge.py                 关键词判定（原 judge）与 LLM 评分
    gate.py                  切换把关
  db/
    eval_runs_repo.py        运行记录（知识库数据库）
  api/public/
    chat.py                  通过 conversation_client 读取上下文、保存消息
    conversations.py         会话列表、消息、删除、反馈；读取历史后按访问范围校验来源
  api/admin/
    feedback.py              通过 conversation_client 读取和处理反馈；转为用例时调用 evaluation
```

- 会话数据只存在会话数据库中，知识库数据库没有 `conversations`、`messages`、`feedback` 表；`eval_runs`、`eval_results`、`eval_cases` 留在知识库数据库。
- 问答应用和管理应用只依赖 `conversation_client`，不能直接引用 `conversation`；`conversation` 也不能引用知识库侧的任何模块。契约见[会话服务](./会话服务.md)第 5 节。
- 问答端通过会话服务写入的是用户自己的数据，符合 ADR 0010 对“问答端对知识库只读”的定义；问答端禁止依赖的列表不变。

## 7. 接口

### 7.1 问答端（`api-public`）

| 方法与路径 | 说明 |
| --- | --- |
| `POST /api/chat` | 请求增加可选的 `conversation_id`；不传时新建会话 |
| `GET /api/conversations?cursor=` | 当前用户的会话列表，按最后更新时间倒序，游标分页 |
| `GET /api/conversations/{id}/messages?before=` | 消息，分页加载；来源已按当前权限校验 |
| `PATCH /api/conversations/{id}` | 修改标题 |
| `DELETE /api/conversations/{id}` · `DELETE /api/conversations` | 删除单个 · 清空全部 |
| `POST /api/messages/{id}/stop` | 停止生成 |
| `POST /api/messages/{id}/regenerate` | 重新生成（同样返回 SSE） |
| `PUT /api/messages/{id}/feedback` · `DELETE` | 提交或修改反馈 · 撤回 |

这些接口由问答应用实现：解析登录用户、转换为 `user_key` 后调用会话服务；会话服务校验资源归属，不属于当前用户时返回 404 而不是 403，不暴露会话是否存在。读取消息时，问答应用再按访问范围处理来源（3.4）。

SSE 事件，属于兼容扩展：

```text
event: meta     {conversation_id, message_id, rewritten_query, persisted, context}   新增，第一个事件
event: sources  [...]                                           不变
event: token    "..."                                           不变
event: done     {message_id, latency_ms}                        增加字段
event: error    {code, message}                                 由字符串改为对象（破坏性，前端同步修改）
```

会话标题取第一个问题的前 30 个字，不额外调用模型。

### 7.2 管理端（`api-admin`）

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/admin/feedback` | 筛选、分页；按文档统计 |
| `GET /api/admin/feedback/{id}` | 详情与追踪信息 |
| `PATCH /api/admin/feedback/{id}` | 状态、原因、处理人、处理说明 |
| `POST /api/admin/feedback/{id}/to-case` | 转为回归用例 |
| `GET /api/admin/eval/runs` · `/runs/{id}` | 运行记录与结果 |
| `GET /api/admin/eval/runs/compare?a=&b=` | 对比两次运行 |
| `PUT /api/admin/eval/cases/{id}` | 编辑用例（现在只能新增和删除） |
| `POST /api/admin/indexes/{id}/activate` | 增加把关检查；`block` 模式下可以传 `force_reason` |

| `web-chat` 消息 | 显示“按‘××’检索”（有改写时）；停止、重新生成；点赞、点踩与原因弹窗；无权查看的来源显示占位 |
| `web-chat` 首次使用 | 隐私说明（3.5） |
| `web-admin` 反馈 | 列表、详情（含追踪信息的可视化：各路召回的排名对比）、转为用例 |
| `web-admin` 回归测试 | 用例编辑（标签、多轮历史、期望文档、参考答案、主体）；运行记录与对比；LLM 评分及理由 |
| `web-admin` 索引列表 | 切换时展示把关结果 |

## 9. 数据模型与迁移

**会话数据库**：`conversations`、`messages`、`feedback` 三张表的结构、跨库引用规则和独立的迁移序列见[会话服务](./会话服务.md)第 6 节。本地模式下是新文件 `data/conversation.db`，首次启动时自动创建，不影响已有的 `data/app.db`。

**知识库数据库**：迁移 3（在阶段 2 的迁移 2 之后）只涉及评测：

```sql
CREATE TABLE eval_runs (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    index_id    INTEGER NOT NULL,
    trigger     TEXT NOT NULL,               -- rebuild / manual / dry_run
    settings    TEXT NOT NULL,
    judge_model TEXT,
    summary     TEXT NOT NULL DEFAULT '{}',
    status      TEXT NOT NULL,               -- running / succeeded / failed / interrupted
    started_at  TEXT NOT NULL,
    finished_at TEXT
);

CREATE TABLE eval_results (
    run_id     INTEGER NOT NULL REFERENCES eval_runs(id) ON DELETE CASCADE,
    case_id    INTEGER NOT NULL,
    case_rev   TEXT NOT NULL,                -- 用例的 updated_at，用于识别“用例已变化”
    answer     TEXT NOT NULL,
    passed     INTEGER NOT NULL,
    judge      TEXT,                         -- {correctness, faithfulness, relevance, reasons}
    retrieval  TEXT,                         -- {hit, recall, rr, candidate_recall}
    trace      TEXT,
    latency_ms INTEGER,
    PRIMARY KEY (run_id, case_id)
);
```

`eval_cases` 增加 `tags`、`history`、`reference_answer`、`enabled`、`source_feedback_id`（会话数据库中反馈的 ID，不建外键）、`updated_at`，全部带默认值，已有用例不受影响。

- `local` 模式下，会话归属于 `user_key = local:local`。
- 消息中的 `answer` 只保存模型原文，与前端“原文是唯一真相源”的约定一致（ADR 0008）。
- 本阶段不需要重建索引。

## 11. 测试与验证

**单元测试**（不调用真实模型）

| 对象 | 覆盖内容 |
| --- | --- |
| 会话 | 会话服务本身的测试见[会话服务](./会话服务.md)第 12 节；这里覆盖问答应用的接入：`user_key` 转换、会话服务不可用时的降级 |
| 历史权限 | 撤销权限后，历史来源显示占位；快照中不含片段正文 |
| 上下文 | 历史截断；生成 Prompt 中不含历史片段 |
| 反馈 | 一人一条、修改、撤回；会话删除后反馈快照仍在 |
| 转为用例 | 预填内容；关联反馈；状态变化 |
| 评测 | 多轮用例走改写；运行记录与对比；用例变化标记；LLM 评分缓存；评分输出不合法时记为“未评分”而不是失败 |
| 把关 | 三条规则；权限用例失败时不可强制；回退不受限制 |
| 保留期限 | 过期会话被清理，未过期的保留 |

**端到端验证**

1. 连续追问三轮（“年假几天？”→“入职 3 年呢？”→“能分开休吗？”），检查改写结果和回答。
2. 点踩一条回答，在后台定位原因并转为用例；修复后重新运行回归测试，确认这条用例由失败变为通过。
3. 构造一个通过率更低的索引版本，确认切换时出现把关提示。
