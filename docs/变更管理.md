# 变更管理

项目演进通过三类文档跟踪，各管一件事，不重复记录：

| 文档 | 回答的问题 | 何时写 |
| --- | --- | --- |
| [`CHANGELOG.md`](../CHANGELOG.md) | 每个版本改了什么 | 每个对外可感知的改动，合入时追加到「未发布」 |
| [`docs/adr/`](./adr/README.md) | 架构为什么这样定 | 做出影响模块边界、数据结构、对外接口或技术选型的决策时 |
| [`docs/架构设计.md`](./架构设计.md) | 现在是什么样 | 架构变化后同步更新，只描述当前状态 |

三者的关系：ADR 记录决策和理由，CHANGELOG 记录决策落地后的结果，架构设计文档始终反映最新状态。

## 模块标签

每条 changelog 条目、每次提交的 scope 都使用下表的标签，按标签就能追溯单个模块的完整演进。

| 标签 | 范围 | 代码位置 |
| --- | --- | --- |
| `rag` | 模型工厂、切分、向量库、检索与生成 | `backend/src/kb_studio/rag/` |
| `ingest` | 增量入库、文档版本、索引版本与重建 | `backend/src/kb_studio/ingest/` |
| `eval` | 回归测试执行与判定 | `backend/src/kb_studio/evaluation/` |
| `db` | 表结构、数据迁移、repo | `backend/src/kb_studio/db/` |
| `storage` | 原文件存储 | `backend/src/kb_studio/storage/` |
| `auth` | 管理员密码、token、接口鉴权 | `backend/src/kb_studio/auth.py` |
| `api` | HTTP 接口契约（路径、参数、SSE 事件） | `backend/src/kb_studio/api/` |
| `web-core` | 前端基础层：接口封装、路由、状态、工具 | `frontend/src/{api,router,stores,utils}/` |
| `web-chat` | 问答界面与暗门 | `frontend/src/views/chat/`、`composables/` |
| `web-admin` | 管理后台各页面 | `frontend/src/views/admin/` |
| `build` | 依赖、构建、启动方式 | `pyproject.toml`、`package.json`、配置文件 |
| `docs` | 文档 | `docs/`、`README.md` |

新增模块时先在这里登记标签，再开始使用。

## CHANGELOG 书写规范

- 格式遵循 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)，分类为：新增、变更、弃用、移除、修复、安全。
- 每条以模块标签开头：``- `ingest` 同名文件内容未变时跳过入库``。跨模块的改动列出主要模块，用 `/` 分隔。
- **写结果，不写过程**：一条一句话，说明行为或能力的变化，不描述实现步骤和排查过程。
- **关键细节要写清楚**：以下情况要补充必要的细节，可以用缩进的子条目：
  - 数据结构或块 ID 规则变化
  - 需要重建索引、迁移数据或重新登录
  - 接口不兼容（在条目前标注 **破坏性**）
  - 有安全影响的改动
- 发布前修掉的问题不记录，只记录相对上一个已发布版本的差异。
- 只改测试、重构且行为不变的改动不进 changelog，在提交记录里体现即可。

## 版本号

遵循 [语义化版本](https://semver.org/lang/zh-CN/)。`1.0.0` 之前：

| 改动 | 版本位 |
| --- | --- |
| 接口不兼容、数据结构变化需要迁移或重建 | 次版本号，`0.x.0` |
| 新增功能、行为调整、修复 | 修订号，`0.x.y` |

版本号同时维护在 `backend/pyproject.toml` 和 `frontend/package.json` 中，两处保持一致。

## 发版流程

1. 把「未发布」下的条目归入新版本，标题写成 `## [x.y.z] - YYYY-MM-DD`。
2. 同步更新两处版本号。
3. 检查 `docs/架构设计.md` 是否反映了本版本的架构变化。
4. 提交，例如 `chore(build): 发布 0.2.0`。使用 Git 时打 tag `vx.y.z`。

## 提交规范

使用 Conventional Commits：`type(scope): 中文描述`，scope 取上面的模块标签。

```
feat(ingest): 同名文件内容未变时跳过入库
fix(web-chat): 输入法组字时回车不再触发发送
docs(adr): 新增 0007 混合检索
```

按模块查看演进：

```bash
grep '`ingest`' CHANGELOG.md          # 版本维度
git log --oneline --grep='(ingest)'   # 提交维度
```
